# Поправки к `_common.md` для облачной сессии (вариант А)

Читать после `docs/ocr_tasks/_common.md`. Там, где правила расходятся, действует этот файл.

## Среда

- Linux-контейнер claude.ai/code: 4 vCPU, около 15 ГБ RAM, **без GPU**, около 30 ГБ диска
  на сессию. Python — `python3`, без `.venv/Scripts/…`. Зависимости ставит setup-скрипт
  окружения; если чего-то не хватает — `pip install` с записью в журнал.
- Обучение — только на CPU. Для CNN бери MobileNetV3-Small или ResNet18 с меньшим батчем.
  Перед полным запуском замерь время эпохи и укладывай запуски в `--max-minutes 9`
  с возобновлением.
- Контейнер временный: всё, что нужно сохранить (код, журнал, отчёты с агрегатами),
  коммить и пушь до конца сессии.

## Данные

- Полных сканов и `data/historical/` в облаке **нет и не будет**. Источник — обезличенный
  пакет (`python -m ocr_lab.cloud_bundle build`), он лежит в приватном репозитории данных
  `AntonYurkovskiy/doc_auto_handling-data`, ветка `main`. Внутри те же пути, что в `data/ocr`:
  `crops/`, `crops_index.csv`, `manifest.csv` (без имён файлов заявок и путей), `labels/`,
  `review/`, `models/digits_v0/` (веса и предсказания T16), `cache/mnist/` (MNIST для синтетики).
- Код `ocr_lab` читает их через `OCR_WORK_DIR` и `OCR_CACHE_DIR`, править пути не нужно.
- Задачи, которым нужен скан целиком (выравнивание, эталоны, прогон «от скана» в T21),
  в облаке не выполняются. Если такая работа попалась — запиши её в «Вопросы к человеку»
  как «выполнить на ПК».
- Не пытайся восстановить, чей это ваучер. Имена судов и агентов в пакете отсутствуют
  намеренно.

## Старт сессии (обязательно, по порядку)

1. Код: `git fetch origin && git checkout -b ocr/cloud-<ID задачи> origin/ocr/handwritten-dates`
   (`<ID>` — T17, T18, …). Работай и пушь в эту ветку. Если среда требует пушить только в
   назначенную ей ветку — пушь туда и назови её в журнале.
2. Данные: `git clone https://github.com/AntonYurkovskiy/doc_auto_handling-data ~/ocr_data`
   (если репозиторий недоступен — остановись и напиши в журнал «нет доступа к данным», ничего
   не выдумывай). Затем
   `export OCR_WORK_DIR=$HOME/ocr_data OCR_CACHE_DIR=$HOME/ocr_data/cache PYTHONPATH=.`.
3. Зависимости, если их не поставил setup-скрипт:
   `pip install -r requirements.txt -r requirements-dev.txt`, затем
   `pip install --index-url https://download.pytorch.org/whl/cpu torch==2.7.1 torchvision==0.22.1`,
   `pip install onnx onnxruntime matplotlib scikit-learn`. Проверь
   `python -c "import torch, torchvision, numpy"` и `OCR_WORK_DIR=... python -m ocr_lab.evaluate --help`.
   Каждую доустановленную зависимость запиши в журнал (в `requirements*.txt` добавляй только
   то, что нужно рантайму или тестам, с `==`).
4. Сверка данных: в `OCR_WORK_DIR/manifest.csv` 772 строки; train / val / test = 623 / 51 / 98
   сканов. Если иначе — остановись и опиши расхождение.

## Возврат артефактов

Модели, предсказания и отчёты в основной репозиторий не коммитятся. В конце задачи:
- скопируй новые каталоги (`models/<имя>_v0/`, `models/*.json`, `reports/<отчёт>/`) в
  `~/ocr_data` по тем же относительным путям;
- `git -C ~/ocr_data add -A && git -C ~/ocr_data commit -m "<ID>: артефакты" && git -C ~/ocr_data push origin main`;
- в журнале перечисли путь каждого артефакта и его размер. Файл больше 90 МБ не пушь —
  опиши в журнале, как его воспроизвести.
Следующая задача цепочки (T17 → T18 → T19 → T20) берёт их оттуда.

## Бюджет и остановка

- Облачные кредиты ограничены. Не запускай обучение «на всякий случай»: перед первым запуском
  оцени время эпохи на CPU и уложись в разумный бюджет.
- Не повторяй один и тот же сбой больше двух раз. После второго — запиши в журнал причину,
  статус «частично» и остановись: решение за человеком.
- Не вызывай subagents и ревью (`--review`, Devin): ревью делает человек на ПК.

## Git

- В облачной сессии коммить **и пушь** в ветку, которую назначила сессия. Пуш здесь —
  единственный способ сохранить работу. `main` не трогай. PR создаётся по запросу человека.
- Модели и производные данные в git по-прежнему не попадают. Веса и ONNX выгружай туда
  же, откуда пришёл пакет: приватный репозиторий данных или хранилище (см.
  `cloud_alternative.md`). Если доступа на запись нет — оставь файлы в
  `OCR_WORK_DIR/models/` и напиши в журнале, что их нужно забрать.
