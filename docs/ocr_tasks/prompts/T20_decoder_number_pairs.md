# T20. Номер ваучера и парные ваучеры в декодере

## Зачем

Из плана, «Этап 3»:
- **Номер ваучера.** Приор по порядку номеров (`predict_next` в
  `app/services/voucher_number.py` уже есть) плюс имя файла. Нумерация идёт по буксиру
  и сбрасывается 1 января (`docs/base_logic.md`).
- **Пары.** Если есть парный ваучер другого буксира, их нужно декодировать вместе.
  В 195 работах есть ваучеры обоих буксиров, и в 131 из них (67 %) все времена совпадают.
  Это два независимых прочтения одного числа, написанного разными людьми.

## Что сделать

### 1. Номер: `decode_number(...)` в `app/ocr/decoder.py` или отдельном модуле

**Кандидаты** — объединение трёх источников:
- top-k от модели (T17);
- окно вокруг ожидаемого следующего номера (буксир, год) ± 15;
- номер из имени файла, если имя разбирается (`parse_voucher_number` после T01).

**Оценка кандидата:**
- `log P_img` через `score_number_candidates`;
- приор последовательности: дискретное распределение с пиком на ожидаемом номере,
  параметры — из `train`;
- штраф за номер, уже подтверждённый для этого (буксир, год). Штраф большой, но не
  бесконечный: копии `(2)` существуют;
- сильный приор имени файла, если в нём чистый номер с кодом буксира.

**Честная оценка на истории.** Ожидаемый номер считай только по ваучерам, которые шли
**раньше** по дате, как в проде. Истинный номер текущего ваучера не подглядывать.

### 2. Пара: `decode_pair(a_inputs, b_inputs, context)`

- Кандидаты: top-N записей каждого ваучера из ядра декодера (T19). Пересчитай пары
  (N × N) с членом связи:
  `log(π · [все времена равны] + (1 − π) · близость(Δ))`.
- `π` и распределение различий — из `train` по `pair_id` манифеста (T02).
- Если второй ваучер уже подтверждён, его значения работают как сильный приор, а не как
  кандидаты.
- В проде пара определяется по одной заявке или работе. Контракт входа опиши так, чтобы
  приложение (T26) могло передать подтверждённый или ожидающий ваучер партнёра.

### 3. Оценка на `val`

Сравни варианты:
1. ядро;
2. ядро + номер;
3. ядро + номер + пары.

Метрики: точность записи целиком, записи с номером, покрытие при точности 99,5 %.
Отдельно — на подмножестве с парами. `test` прогони один раз в конце.

### 4. Тесты: `tests/ocr/test_decoder_pairs.py`

- приор номера вытягивает правильный номер при неуверенной картинке;
- уже использованный номер штрафуется, но выигрывает при очень уверенной картинке;
- пара исправляет неуверенную минуту одного ваучера по уверенной минуте другого;
- пара с реально разными временами не «склеивается».

## Критерии приёмки

- Прирост от номера и от пар измерен на `val`, цифры в журнале.
- Нет утечки: тест доказывает, что приор номера не видит истинный номер текущего ваучера.
- Проверки из `_common.md` зелёные.
