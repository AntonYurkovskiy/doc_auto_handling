# T10. Нарезка кропов для всех сканов и контроль качества

## Зачем

Критерий этапа 1 из плана: лист из 200 случайных кропов по каждому подполю, и дальше идём,
когда больше чем в 98 % кропов значение видно целиком. Здесь режем всё и проверяем этот
критерий.

## Что сделать

1. **`ocr_lab/cut_crops.py`**, запуск `python -m ocr_lab.cut_crops build [--workers 4]`.
   Для каждого скана манифеста:
   - страница из кэша;
   - `detect_variant` (или назначение из `layout_assignment.csv`);
   - `align`, затем `crop_subfields`.
   Результат:
   - кропы `data/ocr/crops/<subfield>/<scan_id>.png`: серые, в исходном разрешении
     эталона, без ресайза;
   - индекс `data/ocr/crops_index.csv`: `scan_id, variant, subfield, path, w, h, align_ok,
     score, inliers, rotated180`;
   - неудачные выравнивания → `data/ocr/reports/align_failures.csv`. Кропы для них не режь.
   Прогон должен быть идемпотентным (готовое пропускается, есть флаг `--force`) и
   параллельным; на Windows — spawn.
2. **Листы контроля.** По каждому из 17 подполей — 200 случайных кропов (`seed=0`):
   2 листа по 100, с индексами и CSV «индекс → scan_id». Используй `ocr_lab/sheets.py` из T04.
3. **Просмотр.** Посмотри все листы и посчитай по подполю кропы, где значение видно
   не целиком. Возможные причины:
   - обрезана цифра;
   - пусто из-за промаха выравнивания;
   - попали цифры соседнего подполя;
   - перевёрнуто.
   Запиши плохие индексы в `data/ocr/review/crops_qc.csv`: `subfield, scan_id, problem`.
4. **Исправления в рамках задачи.**
   - Если проблема системная и понятна (бокс узкий для конкретного варианта), поправь JSON
     макета, перережь это подполе и пересчитай.
   - Если нет — опиши её в журнале.
5. **Отчёт `data/ocr/reports/crops_report.md`:**
   - доля неудачных выравниваний: всего, по вариантам, по годам;
   - видимость по подполям: X из 200, с целью ≥ 196 (98 %);
   - типы проблем;
   - решение по T11: нужна, если неудачных выравниваний больше 5 %.

## Критерии приёмки

- Все сканы манифеста обработаны. Отказы перечислены и не роняют прогон.
- Видимость ≥ 98 % по каждому подполю, либо в журнале объяснено, чего не хватает,
  и есть план.
- Кропы, листы и отчёты лежат в `data/ocr/`, в git только код и журнал.

в точке H2 (5–10 минут), и решение по T11.
