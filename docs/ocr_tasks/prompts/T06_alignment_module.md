# T06. `app/ocr/align.py` — выравнивание по эталону

## Зачем

Рычаг №1 плана — геометрия. Скан выравнивается по эталону бланка гомографией, после чего
подполя режутся по фиксированным боксам. Основа описана в `ocr_dates_guide.md`, «Трек A»
(ORB + RANSAC). Здесь нужен надёжный модуль, проверенный на синтетике. Настройка порогов
на реальных сканах будет в T07.

Сканы CamScanner уже обрезаны и выпрямлены. Поэтому ожидаемая деформация — это масштаб,
сдвиг, поворот на несколько градусов и слабая перспектива. Встречаются перевёрнутые
на 180° страницы.

## Требования к API

Точные имена можешь уточнить, но опиши их в журнале.

```python
@dataclass(frozen=True)
class Reference:        # эталон: серое изображение, маска статичных зон (необязательно), кэш признаков
    ...
def build_reference(image: np.ndarray, mask: np.ndarray | None = None, name: str = "") -> Reference: ...

@dataclass(frozen=True)
class AlignResult:
    ok: bool
    H: np.ndarray | None          # 3x3, скан -> эталон
    warped: np.ndarray | None     # скан в координатах эталона (размер эталона)
    inliers: int
    inlier_ratio: float
    reproj_err: float             # средняя ошибка на инлайерах, px
    score: float                  # пост-проверка совпадения со статичными зонами, 0..1
    rotated180: bool
    method: str                   # например "orb+ecc", "sift", "orb"
    reason: str                   # почему ok=False

def align(scan: np.ndarray, ref: Reference, params: AlignParams = AlignParams()) -> AlignResult: ...
def map_points_to_scan(points_ref: np.ndarray, H: np.ndarray) -> np.ndarray: ...  # для боксов на исходном скане
```

## Как делать

Это ориентиры, не жёсткий рецепт.

- **Признаки.** ORB на 4000–6000 точек, поиск пар через `knnMatch(k=2)` и тест Лоу
  (≈0,75) вместо `crossCheck`. Робастная оценка — `cv2.findHomography` с `USAC_MAGSAC`,
  если он доступен, иначе RANSAC. Признаки эталона считать один раз.
- **Проверка правдоподобия H.** Масштаб в разумных пределах (0,5–2), перспективные члены
  малы. Если оценка не прошла — попробуй скан, повёрнутый на 180°.
- **Уточнение.** ECC (`cv2.findTransformECC`, `MOTION_HOMOGRAPHY`) поверх начальной H,
  на уменьшенной копии и затем на полной. Это даёт субпиксельную точность, которая важна
  для узких боксов цифр.
- **Запасной путь** — SIFT (`cv2.SIFT_create`), если ORB не набрал инлайеров.
- **`score`.** Сравни края (Canny) выровненного скана и эталона внутри маски статичных зон,
  например через IoU расширенных контуров или NCC. Этот показатель отделяет «гомография
  нашлась» от «гомография правильная».
- **Скорость:** не больше 0,5 с на страницу 1654×2339 на CPU по пути ORB+ECC. Замерь.

## Тесты: `tests/ocr/test_align.py`, только синтетика

Генератор синтетического бланка:
- рамки и линии, печатный текст через `cv2.putText`;
- «рукописные» каракули, которые меняются от бланка к бланку;
- размер около 1654×2339.

Случаи:
1. Случайная H: поворот ±4°, масштаб 0,9–1,1, сдвиг, лёгкая перспектива, плюс шум, блюр
   и JPEG. Ошибка перепроецирования углов после выравнивания — меньше 1,5 px.
2. Перевёрнутый на 180° скан → `ok=True`, `rotated180=True`.
3. Чужая картинка (шум или другой «бланк») → `ok=False` с понятным `reason`.
4. `map_points_to_scan` после `align` возвращает точки на исходном скане с точностью
   до 1,5 px.
5. Время на страницу — мягкая проверка с запасом: не больше 2 с, чтобы не ловить
   нестабильность.

## Критерии приёмки

- Все тесты зелёные. Средняя ошибка по 20 случайным H записана в журнал.
- `app/ocr/align.py` зависит только от numpy и opencv.
- Параметры (`AlignParams`) и пороги `ok` вынесены в dataclass: T07 будет их калибровать.
