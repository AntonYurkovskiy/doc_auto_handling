# Альтернатива: решить в облаке

Основной план ([README.md](README.md)) идёт на ПК: `claude -p` / `devin -p`, GTX 1050,
данные на диске. Здесь три облачных варианта, от наименее к наиболее радикальному.

**Что не меняется.** Метод остаётся тем же: геометрия → классификация по малому множеству
→ совместный декодер. Требование «работает локально» относится к **проду**: инференс
в приложении остаётся на CPU через ONNX. Облако меняет место разработки и обучения.
Исключение — вариант В, он меняет и прод.

## Что даёт облачная сессия Claude Code

Замер в этой сессии (claude.ai/code), 2026-09-29:
- 4 vCPU, 15 ГБ RAM, **GPU нет**;
- около 30 ГБ свободного диска на сессию;
- Linux, Python 3.11.

Что это значит:
- **Хватает** для CNN из T16/T17: ResNet18 или MobileNetV3 на ~13 тыс. кропов 64×128
  учатся на CPU за десятки минут. Хватает для декодера, оценки, рантайма и тестов.
- **Не хватает** для дообучения TrOCR-base, Florence-2 и Qwen-VL: нужен облачный GPU
  (вариант Б).
- **Квота та же.** Лимиты Pro общие для claude.ai, Claude Code и Desktop (справочник
  моделей, § 15.1). Облачная сессия тратит те же 5-часовые окна и ту же неделю, что
  `claude -p` на ПК. Облако не даёт больше квоты. Оно даёт:
  - независимость от включённого ПК;
  - PR-процесс с CI и ревью на каждую задачу;
  - воспроизводимое Linux-окружение.
- **Параллельность ограничена квотой.** Одновременно по-прежнему не больше одной сессии
  очереди (D-39): вторая вдвое быстрее выедает окно.

## Вариант А (рекомендую как облачный): «сканы — дома, цифры — в облаке»

Идея: всё, что читает полные сканы (имена судов, агентов, подписи, печати), выполняется
локально. В облако уходит только **обезличенный набор**: кропы цифровых подполей, метки,
сплит и `scan_id`. По кропу дня или минут нельзя понять, чей это документ.

### Раскладка задач

| Где | Задачи | Почему |
|---|---|---|
| ПК, `claude -p` | T00–T04, T06–T12 | Читают полные сканы: истина, выравнивание, эталоны, боксы, нарезка |
| ПК, `claude -p` | **C1** — выгрузка обезличенного набора ([prompts](cloud/C1_cloud_bundle.md)) | Создаёт пакет «кропы + метки», проверяет, что в нём нет лишнего |
| Облако, сессия на задачу | T13, T15–T20, T22, T25 | Работают только с кропами и метками. Обучение на CPU облака |
| Облако | T21 частично | Оценка по кропам и порог. Прогон «от скана» (геометрия) — на ПК |
| Облако | T23, T24 (эксперимент) | Нужны кропы и время выхода — это есть в пакете |
| ПК, `claude -p` | T26–T29 | Интеграция в приложение, БД, UI и приёмка — в целевой среде (Windows) |

Модели и effort по задачам — те же, что в основном плане.

### Подготовка

1. **C0 (человек).** Запушить локальные исходники и документы в GitHub и слить в `main`:
   `voucher_ocr.py`, `voucher_trocr.py`, `ocr_regions.txt`, `docs/ocr_dates_plan.md` и т.д.
   Команды — в переписке с этой сессией (ветка `ocr/local-sources`).
2. **C1 (ПК).** Запустите `python docs/ocr_tasks/run_task.py C1`, промпт —
   `cloud/C1_cloud_bundle.md`. Получится пакет `data/ocr/cloud_bundle/`: кропы PNG,
   `labels.csv`, `README`, около 30–60 МБ.
3. **Хранилище пакета** — одно из двух, решает владелец (вопрос Q6 в `DECISIONS.md`):
   - **приватный репозиторий GitHub** `doc_auto_handling-data`: облачная сессия получает
     к нему доступ так же, как к основному репозиторию. Проще всего;
   - **Yandex Object Storage** (S3-совместимое, данные в РФ). Ключ только на чтение
     лежит в переменных окружения облачного окружения (`OCR_S3_KEY_ID`,
     `OCR_S3_SECRET`, `OCR_S3_BUCKET`), а setup-скрипт скачивает пакет.
4. **Облачное окружение** — в claude.ai/code: меню окружения в заголовке сессии → Edit.
   - **Network access:** PyPI и `download.pytorch.org` (колёса torch CPU и веса
     torchvision). Для T14 ещё `huggingface.co`.
   - **Setup script:**
     ```bash
     pip install -r requirements.txt -r requirements-dev.txt
     pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision
     pip install onnx onnxruntime scikit-learn matplotlib
     ```
   - **Переменные:** `OCR_WORK_DIR` указывает на распакованный пакет.
5. **Правила сессии.** В каждый облачный промпт добавить ссылку на
   [cloud/_cloud_overrides.md](cloud/_cloud_overrides.md): Linux-пути, пакет вместо
   `data/historical`, push в ветку сессии вместо «только коммит».

### Запуск

- **Текст задания** печатает `python docs/ocr_tasks/run_task.py T16 --cloud-prompt`.
  Он велит сессии прочитать `_common.md`, затем `cloud/_cloud_overrides.md`, затем
  промпт задачи.
- **Из терминала ПК:** `claude --cloud "<этот текст>"` — флаг `--cloud` создаёт облачную
  сессию.
- **Или вручную** на claude.ai/code: тот же текст, репозиторий `doc_auto_handling`.
- **Итог задачи — ветка и PR.** CI и ревью (Devin другого вендора) идут по PR.
  Модели, обученные в облаке, возвращаются на ПК через тот же пакетный канал
  (`data/ocr/models/…`): ONNX весит единицы МБ.

### Плюсы и минусы

| + | − |
|---|---|
| ПК свободен, сессии не зависят от него | Та же квота Pro, быстрее не станет |
| PR с CI и ревью на каждую задачу | Нужно выгрузить обезличенный набор: решение владельца (Q6) |
| Чистое воспроизводимое окружение | Нет GPU: для тяжёлых моделей нужен вариант Б |
| Сканы и чувствительные поля не покидают ПК | Windows-специфика и интеграция всё равно проверяются дома |

## Вариант Б: облачный GPU для обучения и «второго мнения»

Когда нужен: CNN на CPU или GTX 1050 упирается в потолок, или нужна независимая вторая
модель. Гайд (`ocr_dates_guide.md`, § 4) и план откладывали QLoRA Qwen-VL только из-за
4 ГБ VRAM.

- **Где:**
  - Yandex DataSphere — посекундная оплата GPU, данные в РФ;
  - Selectel GPU;
  - Kaggle или Colab — бесплатные квоты, но данные уходят в Google: только обезличенный
    пакет;
  - RunPod или Vast.ai.
- **Что открывает:**
  - дообучение TrOCR-small/base и Florence-2-base LoRA на кропах — независимое второе
    мнение. Если CNN и второе мнение согласны, это высокая уверенность;
  - Qwen2.5-VL-7B или Qwen3-VL-8B QLoRA (Unsloth) как **учитель**: переразметка истории,
    поиск шума истины, мягкие метки для CNN.
  - В прод большие модели не идут. Там остаются CNN и декодер, при желании дистиллированные.
- **Как вписать агентов:**
  - облачная или локальная сессия Claude пишет скрипт обучения, ноутбук и `run_gpu.sh`;
  - человек или планировщик запускает его на GPU-хосте;
  - метрики (JSON) и ONNX возвращаются в пакет;
  - следующая сессия оценивает результат через `ocr_lab.evaluate` (T13).
- **Стоимость:** одна-две GPU-сессии по 1–3 часа на A10/L4-классе. Цены провайдеров
  проверить на дату запуска.

## Вариант В: облачная vision-модель как распознаватель

Этот вариант **противоречит требованию «всё локально»** для прода. Его разумная роль —
инструмент разработки. В прод он идёт только с явного решения владельца.

- **Схема:**
  - на модель уходит не скан, а **плитка из 17 кропов** одного ваучера с подписями полей;
  - vision-модель возвращает JSON с top-3 значениями на подполе;
  - ответ идёт в тот же декодер (T19) как ещё одно правдоподобие или как «второе мнение»
    рядом с CNN.
- **Кандидаты:**
  - Claude Haiku 4.5 или Sonnet через API;
  - `claude -p` по подписке — в пределах квоты, для разовых прогонов по истории;
  - Yandex Vision OCR (есть модель для рукописного текста; проверить качество на цифрах).
- **Стоимость, оценка:** изображение ≈ ширина × высота / 750 токенов, плитка
  1200×600 ≈ 1 тыс. токенов плюс промпт. Выходит около $0,003 на ваучер на Haiku 4.5
  и около $0,005 на Sonnet. Вся история (774) — единицы долларов, месяц работы — центы.
  Batch API снижает цену вдвое.
- **Где полезен уже сейчас, без изменения прода:** независимое прочтение всей истории
  для поиска шума в истине. Это заменяет часть ручной работы в точках H1 и H3. В плане
  его роль может сыграть расширенная T04: не 70 ваучеров, а все 774, пакетно.
  Пример промпта — [cloud/C2_vlm_second_reading.md](cloud/C2_vlm_second_reading.md).
- **Минусы:**
  - внешний сервис и сеть в контуре;
  - нет откалиброванных вероятностей: самооценка модели или сэмплирование;
  - доступность API из РФ и политика владельца.

## Сравнение

| | Основной (ПК) | А: гибрид | Б: + облачный GPU | В: облачная VLM |
|---|---|---|---|---|
| Где агенты | ПК | ПК + облако | ПК/облако + GPU-хост | любое |
| Полные сканы покидают ПК | нет | нет | нет | нет, только плитки цифр |
| GPU | GTX 1050, 4 ГБ | нет (CPU) | 24–80 ГБ | не нужен |
| Квота Claude | ≈ 4–5 окон | та же | та же + GPU-часы | + API или квота на прогоны |
| Прод локальный | да | да | да | нет, если в прод |
| Когда выбирать | по умолчанию | ПК занят или выключен; нужен PR-процесс | CNN упёрлась в потолок | быстрая чистка истины; прототип без обучения |

## Рекомендация

1. Идти основным планом на ПК.
2. **Вариант В — как инструмент разработки**, если владелец разрешит (Q5): прогнать
   историю один раз, чтобы найти шум в истине до обучения. Это дёшево, а шум в метках —
   одна из главных угроз точности (4 из 11 нарушений цепочки уже оказались ошибками
   выгрузки).
3. **Вариант А** — если ПК нужен для другой работы или важен PR-процесс.
4. **Вариант Б** — только по цифрам: если после T21 покрытие автоприёма при точности 99,5 %
   явно ниже цели, а разбор ошибок показывает, что виновато распознавание, а не геометрия
   или истина.
