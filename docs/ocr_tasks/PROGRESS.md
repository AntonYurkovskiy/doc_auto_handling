# Журнал задач OCR-плана

Сюда каждая задача `T*` дописывает раздел по шаблону из `_common.md`, § 8.
Раннер (`run_task.py --status`) считает задачу выполненной, если в её разделе стоит
строка `- Статус: готово`.

Правила:
- новые разделы — только в конец;
- чужие разделы не редактировать;
- исправления — отдельной строкой в своём разделе.

## T06 — Модуль выравнивания скана по эталону (облако) (2026-09-29)
- Статус: готово
- Сделано:
  - `app/ocr/__init__.py` — пустой пакет (только докстринг, чтобы не конфликтовать с T13/T19);
  - `app/ocr/align.py` — ORB (knnMatch + тест Лоу 0,75) → `findHomography(USAC_MAGSAC)` →
    проверка правдоподобия → ECC `MOTION_HOMOGRAPHY` на копии 0,5 → `score` по краям в
    статичных зонах; запасной путь SIFT; повтор на скане, повёрнутом на 180°;
  - `tests/ocr/synth.py` — генератор синтетического бланка 1654×2339 (рамки, таблица,
    `putText`, «рукопись» по `fill_seed`, маска полей), случайная H, деградация (блюр,
    шум σ=6, JPEG 70), ошибка углов;
  - `tests/ocr/test_align.py` — 17 тестов: 6 случайных H, 180° (с повтором и без),
    чужие картинки (шум, другой бланк, пустой лист), `map_points_to_scan`, BGR-вход,
    падение `score` при сдвиге, SIFT-fallback, время;
  - `requirements.txt`: `numpy==2.4.6`, `opencv-python-headless==5.0.0.93` (рантайм
    выравнивания; в облаке их не было, поставлены pip).
- Цифры (синтетика, 20 случайных H: поворот ±4°, масштаб 0,9–1,1, сдвиг ±40 px,
  перспектива ±2e-5, шум+блюр+JPEG; CPU 4 vCPU):
  - ошибка углов эталона после выравнивания: средняя 0,107 px, худший случай 0,186 px
    (с `ecc_full_res=True`: 0,028 / 0,081 px, но 1,8 с на страницу);
  - без ECC — до ~2 px, ECC обязателен;
  - время на страницу (ORB+ECC): среднее 0,30–0,34 с, максимум 0,39 с; эталон строится 0,36 с;
  - инлайеров 287–991, доля 0,73–0,85; `reproj_err` 1,2–1,9 px (шум положения ключевых
    точек на копии, а не ошибка выравнивания); `score` верных 0,996–1,0;
  - `score` при сдвиге H на (3; 1,5)/(5; 2,5)/(10; 5) px: 0,91/0,84/0,57; другой бланк
    в тождественной H: 0,23–0,33; порог `min_score=0,6`;
  - чужие картинки отсекаются ещё на признаках (≤12 инлайеров из ≥40), 0,2–0,6 с.
- Решения без человека:
  - признаки ищутся на копии с длинной стороной 1200 px (скорость), точки переводятся в
    полный размер; порог RANSAC — 3 px на копии;
  - ECC: грубый проход на 0,5 с `eps=1e-4` (итерации не влияют — сходится за несколько);
    полноразмерный проход выключен по умолчанию (`ecc_full_res`), т. к. в 5 раз медленнее;
    результат ECC отбрасывается, если уводит углы > 8 px от оценки по признакам;
  - 180° определяется по углу H (ORB инвариантен к повороту); явный повтор с
    `cv2.rotate` — только если прямая попытка не прошла;
  - `score` = F1 совпадения краёв Canny (копия 0,5, допуск 1 px) внутри маски статичных
    зон; радиус 2 насыщался до 1,0 при сдвиге 3 px и давал 0,44 чужому бланку;
  - `ORB.create`/`SIFT.create` вместо `ORB_create`: в стабах opencv 5 нет `*_create`;
  - генератор синтетики лежит в `tests/ocr/synth.py`, чтобы его могли переиспользовать тесты
    T07+.
- Вопросы к человеку:
  - выполнить на ПК: калибровка порогов на реальных сканах (T07) — в облаке сканов нет;
  - opencv 5.0 выбран как текущий в pip; если на ПК уже стоит 4.x — модуль совместим с
    ≥4.5.1 (нужны `USAC_MAGSAC`, `SIFT`), версию в `requirements.txt` можно понизить.
- Для следующих задач:
  - API (`app.ocr.align`): `AlignParams` (frozen, все пороги), `build_reference(image,
    mask=None, name="", params=None) -> Reference`, `align(scan, ref, params=None) ->
    AlignResult`, `alignment_score(scan, H, ref, params=None) -> float`,
    `map_points(points, H)`, `map_points_to_scan(points_ref, H)`;
  - `AlignResult`: `ok, H (скан→эталон, поворот 180° уже учтён), warped (размер эталона,
    каналы скана сохраняются), inliers, inlier_ratio, reproj_err, score, rotated180,
    method ("orb+ecc" | "orb" | "sift+ecc" | "sift"), reason`; при `ok=False` `H` может
    быть заполнена для диагностики;
  - пороги `ok` по умолчанию: `min_inliers=40`, `min_inlier_ratio=0.15`,
    `max_reproj_err=3.0`, `min_score=0.6`; правдоподобие: масштаб 0,5–2, анизотропия ≤1,25,
    поворот ≤15° от 0°/180°, перспектива `|h31|·W+|h32|·H ≤ 0.15`;
  - `params` эталона и `align` должны совпадать по масштабам (`ecc_scale`, `score_scale`):
    по умолчанию `align` берёт `ref.params`;
  - маска эталона: 255 — статичные зоны (линии, печать), 0 — поля рукописи; без маски
    рукопись снижает `score` и мешает ECC;
  - слабые места: на реальных сканах `score` будет ниже синтетического (другая печать,
    тени, мятые листы) — `min_score` калибровать в T07; нелинейные деформации (изгиб листа)
    гомография не описывает; ORB на пустом/очень бледном скане не находит признаков.
