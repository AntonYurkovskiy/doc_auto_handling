# Журнал задач OCR-плана

Сюда каждая задача `T*` дописывает раздел по шаблону из `_common.md`, § 8.
Раннер (`run_task.py --status`) считает задачу выполненной, если в её разделе стоит
строка `- Статус: готово`.

Правила:
- новые разделы — только в конец;
- чужие разделы не редактировать;
- исправления — отдельной строкой в своём разделе.

    `cv2.rotate` — только если прямая попытка не прошла;
  - `score` = F1 совпадения краёв Canny (копия 0,5, допуск 1 px) внутри маски статичных
    зон; радиус 2 насыщался до 1,0 при сдвиге 3 px и давал 0,44 чужому бланку;
  - `ORB.create`/`SIFT.create` вместо `ORB_create`: в стабах opencv 5 нет `*_create`;
  - генератор синтетики лежит в `tests/ocr/synth.py`, чтобы его могли переиспользовать тесты
    T07+.
- Вопросы к человеку:

  - opencv 5.0 выбран как текущий в pip; если на ПК уже стоит 4.x — модуль совместим с

## T19 — Совместный декодер записи ваучера — ядро (облако) (2026-09-29)
- Статус: частично
- Сделано:
  - `app/ocr/decoder.py` (только numpy и stdlib): модель «картинка + приоры + жёсткие правила»,
    точный поиск, контракт dataclass-ами — `DecodeContext`, `DecoderModel` (`DecoderPriors`,
    `DecoderWeights`, `SearchParams`), `DecodeResult`, `Record`, `RowValue`, `RowOption`.
    Вход — `{подполе: [(значение, p), …]}`, как у `runtime.predict_digits`.
  - Поиск: запись = базовая дата B × шаблон смещений дней × (час, минута) по строкам. При
    фиксированном шаблоне оценка — цепочка с унарными и парными членами, поэтому:
    нормировка и маргиналы — точная сумма-произведение батчем по всем B; top-N — точное
    k-лучшее ДП с отсечением цепочек по их точному максимуму.
  - Приоры по умолчанию из цифр плана (`DecoderPriors.default()`), декодер работает без файла.
  - `ocr_lab/fit_decoder_priors.py`: приоры из `train` манифеста (колонки T02), веса —
    покоординатный поиск по сетке на val-предсказаниях T13 (цель — среднее
    лог-правдоподобие истинной записи при softmax по перечисленным). Запись —
    `data/ocr/models/decoder_priors_v0.json`. Проверен только на синтетическом манифесте.
  - Тесты: `tests/ocr/test_decoder.py` (все 9 пунктов промпта и граничные случаи),
    `tests/ocr/test_fit_decoder_priors.py`. Пустые `app/ocr/__init__.py`,
    `ocr_lab/__init__.py`, `tests/ocr/__init__.py`.
  - Не сделано: пункт «Оценка» на `val` (нет манифеста, моделей T16/T18 и предсказаний
    `digits_v0` в облаке) — отложено до ПК. Критерий «декодер повышает точность записи
    на `val`» и кривая «покрытие — точность» пока не проверены.
- Цифры (синтетика, CPU облака 4 vCPU):
  - время `decode`: типичный ваучер ≈ 6 мс, «размазанные» распределения (6 значений на
    подполе) ≈ 18 мс, пропущен один час ≈ 10 мс; худшие случаи (пропущены все часы или
    вход пустой, есть время заявки) ≈ 32–35 мс;
  - сверка с полным перебором на 12 случайных входах (в том числе `max_day_offset=2`,
    пропуски, время заявки, отсечение базовых дат): `log Z`, оценки top-12 и маргиналы
    совпадают до 1e-8;
  - синтетический манифест (223 train, 37 val, 10 % ошибок top-1 на подполе): запись
    целиком «top-1 по полям» — 29,7 %, декодер — 100 %; среднее log p(истины)
    −0,054 → −0,016 после подбора весов.
- Решения без человека:
  - Минуты (DECISIONS Q1): приор по умолчанию — кратные 10 делят 99,8 %, кратные только 5 —
    0,19 %, прочие — 0,01 %. Штраф 45 против 40 ≈ 6,3 нат: 45 выигрывает, только если
    картинка уверена в нём в сотни раз сильнее. В кандидаты минут всегда добавляются
    00…50.
  - Полночь (Q2): `24:00` на бланке = дата строки + час 24, минуты только 00; фактическое
    время — 00:00 следующих суток. Приор часов по умолчанию равномерный по 0–24, поэтому
    24 не штрафуется относительно 00.
  - Смещения дней: `o ∈ {0, 1}` по умолчанию (шаблоны 0000/0001/0011/0111 с частотами
    97,8 / 1,0 / 0,6 / 0,6 %); скрипт поднимает максимум до 2, если такое есть в `train`.
  - Длительности по умолчанию: смесь «ноль» (1 %), логнормаль (медианы 40 / 90 / 40 мин,
    σ = 0,8) и тяжёлый хвост (7 %, медиана ×3, σ = 1,5), пол 1e-9 на минуту.
    Бины: шаг 10 мин до 6 ч, дальше шире, до 3 суток.
  - Заявка: кусочно-постоянная плотность от −10 до +10 суток (медиана +4 ч, 43 % в ±3 ч,
    p99 = +6 суток), вне — пол 1e-8 на минуту: окна нет.
  - Год: B — в году контекста; переход через Новый год внутри ваучера даёт календарная
    арифметика. Год времени заявки и `extra_years` допускаются со штрафом −3 нат.
  - Если дни не прочитаны вовсе, B берётся из окна −10…+3 суток от заявки, а без заявки
    результата нет (флаг `no_candidates`).
  - `confidence` — softmax по всему перечисленному пространству, а не только по top-N.
    `margin = p1 − p2`.
  - Сглаживание эмпирики в скрипте — псевдосчётчиками к приорам по умолчанию; вид работ
    получает свои длительности при ≥ 60 ваучерах в `train`.
  - После слияния с T06/T13 скрипт берёт пути из `ocr_lab.paths` (`MANIFEST`, `MODELS_DIR`)
    и читает JSONL через `ocr_lab.predictions.read_predictions`.
  - Новых зависимостей нет: `numpy==2.4.6` в `requirements.txt` уже добавила T06.
- Вопросы к человеку:
  - Выполнить на ПК: `python -m ocr_lab.fit_decoder_priors --pred <val_predictions.jsonl
    digits_v0>`, затем прогон `val` через декодер → JSONL T13 → `ocr_lab.evaluate`
    (сравнение «top-1 по полям» и «декодер», ошибка в минутах, кривая «покрытие —
    точность»). После этого статус можно поднять до «готово».
- Для следующих задач:
  - API: `decode(inputs, DecodeContext(year, app_dt=None, work_type=None, extra_years=()),
    DecoderModel.load(path_or_None)) -> DecodeResult`. `DecodeResult.to_json()` даёт
    `records`, `confidence`, `margin`, `flags`, `missing`, `overridden` для строки JSONL T13.
    `Record.to_json()` — формат T13: `24:00` хранится как 00:00 следующих суток плюс
    `hour24`.
  - `DecodeResult.marginals[row]` — top-3 `RowOption(value: RowValue, p)` для кнопок UI
    (T27). `RowValue` хранит написание (дата на бланке, час 0–24, минута) и `.dt`.
  - Флаги: `fields_top1_chain_violation`, `fields_top1_bad_hour24`,
    `fields_top1_invalid_date`, `fields_top1_day_mismatch`, `decoder_override`,
    `crosses_midnight`, `hour24`, `minute_not_mult10`, `app_far` (|Начало − заявка| > 24 ч),
    `other_year`, `missing_subfields`, `no_candidates`.
  - T20: `score_record(forms, inputs, context, model)` — ненормированная оценка любой
    записи. Для пар берите `records` (top-N, `score`, `p`) и `log_z`.

    (`normalize_work_type`), иначе берутся общие длительности.
