# T01. Разбор номера ваучера из имени файла: кириллица

## Проблема

`parse_voucher_number` в `app/services/voucher_number.py` понимает только латинские `k` и `p`
(регулярное выражение `_VOUCHER_NAME_RE`). В истине, в колонке `voucher_file` файла
`reconciled_dataset.csv`, встречаются имена с кириллическими «к» и «а». Их функция не
разбирает, и `predict_next` такие ваучеры не видит. Путь к CSV — в `CONTEXT.md`.

Правило нумерации из `docs/base_logic.md`:
- номер считается отдельно по каждому буксиру и сбрасывается 1 января;
- маркер копии `(N)` игнорируется;
- `k` — Коммунар, `p` — Пионер.

## Что сделать

1. **Разведка без коммита.** Прогони текущий `parse_voucher_number` по всем уникальным
   `voucher_file`. Сгруппируй имена, которые не разобрались или разобрались без кода
   буксира, по шаблону (цифры заменить на `N`) и посчитай каждую группу. Для каждой группы
   посмотри, что стоит в колонке `tug` у этих строк.
2. **Нормализация омоглифов до разбора:**
   - кириллические `к` и `К` → `k`;
   - кириллические `р` и `Р` → `p`, если такие есть.
3. **Имена с «а».** По колонке `tug` выясни, что означает эта буква.
   - Если все такие строки относятся к одному буксиру и это явная опечатка кода — добавь
     соответствие и комментарий с обоснованием.
   - Иначе ничего не угадывай: функция возвращает `(номер, None)`, а в «Вопросы к человеку»
     попадают шаблоны и их количество.
4. **Инварианты:** маркер копии `(N)` по-прежнему игнорируется; пробелы по краям допустимы;
   регистр не важен.
5. **Тесты** в `tests/test_voucher_number.py`: кириллица, смешанный регистр, `(2)`,
   неразбираемые имена.

## Критерии приёмки

- Существующие тесты по смыслу не менялись и проходят. Новые тесты тоже проходят.
- В журнале: сколько имён не разбиралось до правки и после, по шаблонам.
- Остальные модули не тронуты.
