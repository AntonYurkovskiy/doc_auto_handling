# T16. CNN для двузначных подполей

## Зачем

Основной распознаватель плана — одна модель на все двузначные подполя. Её выход нужен
не как одно значение, а как **откалиброванное распределение вероятностей** по значениям:
его использует совместный декодер (T19). Метрика выбора модели — точность подполя на `val`,
а не loss.

## Что сделать

### 1. `ocr_lab/models.py`

- **Бэкбон:** torchvision ResNet18 или MobileNetV3-Small с весами ImageNet. Серый вход:
  1 канал, веса первой свёртки просуммировать по каналам. Веса скачиваются в `TORCH_HOME`
  на E: (см. `ocr_lab/paths.py`).
- **Головы:** `tens` (11 классов, 10 = «пусто») и `units` (10 классов). Опционально —
  embedding `part_id`, приклеенный перед головами. Сравни на `val` с ним и без него.

### 2. Функция потерь

- `units`: обычная кросс-энтропия.
- `tens`:
  - для значений ≥ 10 — кросс-энтропия;
  - для значений < 10 — **маргинальное правдоподобие** `-logsumexp(logp[0], logp[empty])`,
    потому что истина не знает, писали «09» или «9».

### 3. Распределение по значениям

`P(v) ∝ P(tens(v)) · P(units(v))`, нормировано по допустимому диапазону части:
- день — 1–31;
- месяц — 1–12;
- часы — 0–24, где 24 допустимо (декодер разрешит его только с минутами 00);
- минуты — 0–59.

Для v < 10: `P(tens(v)) = P(tens=0) + P(tens=empty)`. Выдай top-5 значений в формат T13.

### 4. `ocr_lab/train_digits.py`

- **Оптимизация:** AdamW, lr около 1e-3 для голов и 3e-4 для бэкбона, cosine-расписание,
  батч под VRAM (замер из T05). FP32, без AMP: GTX 1050 — это Pascal.
- **Ранняя остановка** по средней точности подполей на `val`. Лучший чекпоинт — по ней же.
- **Воспроизводимость:** seed, `config.json`, `history.csv` по эпохам.
- **Ограничение Bash на 10 минут:** флаг `--max-minutes`, сохранение состояния каждую
  эпоху и `--resume`. Либо фоновый запуск с опросом лога.
- **Эксперименты** — не больше 4 запусков в рамках задачи:
  - бэкбон ResNet18 против MobileNetV3;
  - с `part_id` и без;
  - синтетика MNIST: включена или выключена;
  - разумные эпохи 30–60.
  Все результаты — в журнал.

### 5. Выход

- `data/ocr/models/digits_v0/`: `best.pt`, `config.json`, `history.csv`;
- предсказания `val_predictions.jsonl` и `test_predictions.jsonl` в формате T13;
- оценка через `python -m ocr_lab.evaluate` для `val` и `test`.

### 6. Разбор ошибок

- Лист из 60 худших ошибок на `val`: кроп, истина, top-3 с вероятностями.
- Посмотри его и раздели ошибки на «модель ошиблась», «плохой кроп» и «похоже на ошибку
  истины». Последние запиши в `truth_corrections.csv` со `status=proposed`, `source=T16`.
- Если в DECISIONS.md просмотр сканов моделью запрещён, лист оставь человеку.

## Критерии приёмки

- **Сравнение с бейзлайном.** Таблица в журнале «бейзлайн T14 против CNN» по частям и
  по ваучеру целиком на `val` и `test`. CNN должна быть заметно лучше. Если нет —
  разбор причин вместо подгонки.
- **Честная оценка.** `test` не использовался ни для выбора модели, ни для
  гиперпараметров. Прямо напиши это в журнале.
- **Проверки** из `_common.md` зелёные. Юнит-тесты на функцию потерь и на сборку
  распределения по значениям: маргинализация ведущего нуля, 24, нормировка.
