# T07. Варианты бланка, эталоны и пороги выравнивания

## Зачем

Из плана: у буксиров разные бланки. У Коммунара шрифт с засечками, у Пионера —
машинописный Courier, и строки стоят в других местах. Нынешний шаблон один и размечен
по 243k (Коммунар). Нужно:
- перечислить варианты бланка (минимум два; проверить, нет ли версий внутри одного буксира);
- для каждого варианта сделать эталон;
- откалибровать пороги модуля `app/ocr/align.py` (T06) на реальных сканах.

## Что сделать

1. **Начальные эталоны.** Для каждого буксира отбери 12 кандидатов по метрикам: высокий
   контраст, малый наклон, типичный размер. Смотреть можно только **обезличенные** миниатюры:
   зоны буксира, судна, агента, вида работ, примечаний, «совместно с», подписей и печатей
   замазаны белым (правило Q5 в `_common.md`). Выбери самый чистый скан.
2. **Выравнивание всех страниц буксира** по начальному эталону. Метрики (`ok`, `score`,
   `inliers`, `reproj_err`, `rotated180`) сохрани в `data/ocr/layout_assignment.csv`.
3. **Поиск вариантов.**
   - Посмотри лист из 48 худших по `score` — тоже обезличенные миниатюры.
   - Если видишь другой макет (старая версия бланка, другая вёрстка) и таких сканов
     не меньше 15 — это отдельный вариант со своим эталоном.
   - Остальные плохие случаи опиши как типы: обрезано, сильный наклон, не тот документ,
     две страницы и т.п.
4. **Статичный эталон для каждого варианта.**
   - Выровняй 30 лучших сканов варианта.
   - Возьми попиксельную медиану: рукопись и переменный текст исчезают, остаётся форма.
   - Маска статичных зон — пиксели, тёмные в большинстве выровненных сканов.
   - Сохрани в `data/ocr/layouts/<variant>/`: `reference.png`, `static_mask.png`,
     `meta.json` (размер, исходные `scan_id`, параметры).
   - Имена вариантов: `kommunar_v1`, `pioneer_v1`, …
5. **Повторное выравнивание** всех страниц по статичным эталонам. Сравни долю `ok` с шагом 2.
6. **Калибровка порогов `ok`.**
   - Собери наложения: края эталона цветом поверх выровненного скана. Возьми по 8 штук из
     разных диапазонов `score`, посмотри их.
   - Выбери порог, отделяющий правильные выравнивания от неправильных.
   - Запиши его в `AlignParams` по умолчанию или в `meta.json` варианта и обоснуй в журнале.
7. **`detect_variant`.** Функция в `app/ocr/align.py` или новом `app/ocr/variants.py`.
   Она выравнивает скан по каждому эталону и берёт лучший `score`. В проде буксир может
   быть неизвестен. Проверь на всех страницах, как часто вариант совпадает с буксиром
   из манифеста.
8. **Отчёт `data/ocr/reports/layouts_report.md`:**
   - варианты и число сканов в каждом;
   - доля `ok` по вариантам и годам — до и после статичного эталона;
   - типы отказов;
   - точность `detect_variant`;
   - время на страницу.

## Критерии приёмки

- Для каждого варианта есть `reference.png` и `meta.json`. `detect_variant` совпадает
  с буксиром из манифеста не меньше чем в 99 % выровненных сканов.
- Доля неудачных выравниваний названа. Если она больше 5 %, в журнале есть рекомендация
  запускать T11.
- Эталоны и наложения не коммитятся: это производные от реальных сканов.
  Коммитятся только код и журнал.

## Отчёт

Журнал по шаблону. В «Для следующих задач» — список вариантов, пути к эталонам, пороги,
API `detect_variant`.
