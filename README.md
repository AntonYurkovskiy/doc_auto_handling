# doc_auto_handling

Сервис автоматизации обработки **заявок** и **ваучеров** буксира:
приём документов → извлечение полей → сопоставление → расчёт стоимости → БД → экспорт.

Заменяет ручную секретарскую работу: разбор писем-заявок, ввод ваучеров,
сопоставление, расчёт по тарифам с курсом ЦБ РФ и производственным календарём.

## Архитектура (MVP)
Монолит **FastAPI + SQLite (WAL)**, модули пайплайна — чистые функции
(готовы к выносу в отдельный worker при росте нагрузки).

```
app/
  config.py            # настройки + ТАРИФНЫЕ КОНСТАНТЫ (плейсхолдеры — заменить на реальные)
  database.py          # подключение SQLite (WAL), сессии
  models.py            # схема БД (по matching.xls): applications, vouchers, works + справочники
  main.py              # FastAPI: приём, ручной ввод, сопоставление, расчёт, экспорт
  services/
    application_parser.py  # разбор заявок (HTML .eml / текстовый PDF)
    voucher.py             # разбор ваучеров и подготовка предсказаний
    voucher_template.py    # эталонный макет и регионы ваучера
    matching.py            # сопоставление заявка↔ваучер (судно+вид работ+дата)
    calculation.py         # расчёт: тарифы, курс ЦБ, ночь/праздник, сопровождение
    cbr.py                 # курс валют ЦБ РФ (cbr.ru)
    calendar_ru.py         # рабочий/выходной день (isdayoff.ru + откат на выходные)
    export.py              # экспорт Excel/CSV (формат matching.xls), импорт справочников
  web/                 # шаблоны Jinja2 + статика (минимальный UI)
data/                  # SQLite и загруженные файлы (в .gitignore)
```

## Тарифы
Реальные ставки — коммерческая тайна и в репозитории **не хранятся**.
В `app/config.py` стоят **условные константы** (`RATES`, `RATES_PER_OPERATION`),
чтобы работала логика расчёта. Проставь реальные значения `rate` — логика не меняется.

Правила (подтверждены заказчиком):
- 1 у.е. = 1 USD; ставки заведены только для агента Транс-Агро (90% заявок);
- почасовые услуги тарифицируются **пропорционально минутам**: `ставка × минуты / 60`;
- швартовка/отшвартовка для судов ≥2000 GRT — **за регистровую тонну** (GRT из заявки),
  сумма делится на число буксиров, работавших совместно (строка ваучера «совместно с …»):
  1 буксир → /2, 2 буксира → /3 и т.д.;
- суда <2000 GRT — фиксированная сумма **за операцию** (будни / праздник+ночь);
- ночное время **22:00–06:00**; праздники/выходные — из производственного календаря;
- ледовые условия — ручной флажок в ваучере;
- «Сопровождение» — часы вводятся вручную (авто-разбор примечаний ваучера — позже);
- выручка в рублях = `сумма × курс ЦБ` на дату завершения работ (для рублёвых договоров курс = 1).

## OCR ваучеров

Распознавание сканов ваучеров реализовано через **Tesseract** + `pytesseract`.

1. Установи Tesseract:
   - **Windows**: скачай установщик с [UB Mannheim](https://github.com/UB-Mannheim/tesseract/wiki)
     (или `choco install tesseract`) и убедись, что `rus` и `eng` языковые пакеты выбраны.
   - **Linux**: `sudo apt-get install tesseract-ocr tesseract-ocr-rus tesseract-ocr-eng`
   - **macOS**: `brew install tesseract tesseract-lang`
2. Убедись, что `tesseract` доступен в `PATH`.
3. (Опционально) Переопредели путь в `.env`:
   ```
   APP_TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
   ```

OCR запускается при загрузке ваучера и подтверждении. Если Tesseract не найден,
приложение продолжает работать на приорах (история + заявка).

Рукописные поля даты/времени («Выход из базы», «Приход в базу», «Начало работ»,
«Окончание работ») распознаются **TrOCR** — моделью
[`kazars24/trocr-base-handwritten-ru`](https://huggingface.co/kazars24/trocr-base-handwritten-ru)
(transformers + torch, см. `requirements.txt`). При первом запуске веса
скачиваются в кэш HuggingFace (~1.4 ГБ). Настройки в `.env`:

```
APP_TROCR_ENABLED=true       # false — сразу Tesseract для всех полей
APP_TROCR_MODEL=kazars24/trocr-base-handwritten-ru
APP_TROCR_DEVICE=            # пусто — авто (cuda при наличии), иначе cpu/cuda/mps
APP_TROCR_MAX_NEW_TOKENS=32
```

Если TrOCR недоступен (нет torch/transformers или не скачались веса),
рукописные поля откатываются на Tesseract, затем на приоры.

Поле «Вид работ» после OCR нормализуется: в распознанной строке ищутся
наименования услуг договора Транс-Агро (`CONTRACT_SERVICES` в `app/config.py`),
при вхождении подставляется услуга из договора (несколько услуг — через « + »).
Номер ваучера и буксир берутся из имени файла (`323p.pdf` → № 323, БК Пионер),
судно — из сопоставленной заявки: эти источники приоритетнее OCR.

## Приём заявок по IMAP
Настрой доступ к почте через переменные окружения (`.env`, см. `.env.example`):
`APP_IMAP_HOST` (по умолчанию `imap.yandex.ru`), `APP_IMAP_PORT`, `APP_IMAP_SSL`,
`APP_IMAP_USER`, `APP_IMAP_PASSWORD`, `APP_IMAP_FOLDER`, `APP_APPLICATION_SENDER`
(фильтр отправителя — необязательно). Для Яндекса с 2FA нужен **пароль приложения**,
а не основной пароль. Логин/пароль в репозиторий не коммитятся.

Забрать непрочитанные письма-заявки:
```bash
python scripts/fetch_mail.py
```
или кнопкой «Получить почту (IMAP)» на странице «Заявки». Оригиналы `.eml`
сохраняются в `data/incoming/applications`, вложения (PDF/скан) — в
`data/incoming/vouchers`, для каждой заявки создаётся запись со статусом
`needs_review`. Повторный приём не дублирует письма (дедуп по `Message-ID`).

- **Фаза 1 (готово):** каркас, БД, ручной ввод, парсер заявок, расчёт, экспорт.
- **Фаза 2:** приём заявок по IMAP, авто-парсинг PDF заявок «Fwd_…».
- **Фаза 3:** модель ваучера, фиксированные регионы и ручное подтверждение предсказаний.
- **Фаза 4:** OCR сканов ваучеров по регионам шаблона (Tesseract).
- **Фаза 6:** локальная vision-модель для рукописи, worker (RQ), PostgreSQL, интеграция с корп-программой.
