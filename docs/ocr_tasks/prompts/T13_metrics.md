# T13. Единый формат предсказаний и модуль оценки

## Зачем

Дальше будет несколько распознавателей: TrOCR-бейзлайн (T14), CNN (T16, T17) и декодер
(T19–T21). Сравнивать их нужно одинаково. Метрики из плана («Этап 2»):
- точность по подполю, по метке времени и по ваучеру целиком;
- отдельно для печатного и рукописного и отдельно по буксирам;
- ошибка в минутах, потому что от неё зависят деньги.

Как считаются деньги (`app/services/calculation.py`):
- по интервалам Начало → Окончание (`work_minutes`) и Выход → Приход (`busy_minutes`);
- ночной тариф — по началу работ (`settings.night_start_hour`, `night_end_hour`);
- курс — по дате окончания.

## Что сделать

### 1. `ocr_lab/predictions.py` — формат JSONL, одна строка на скан

```json
{"scan_id": "2026_243k", "source": "cnn_v0",
 "fields": {"left_base.hour": [[9, 0.93], [8, 0.05]], "voucher_number": [[243, 0.9]], "...": []},
 "records": [{"left_base": "2026-07-02T09:10", "arrived_base": "...", "started_work": "...",
              "finished_work": "...", "hour24": ["arrived_base"], "voucher_number": 243, "p": 0.97}],
 "confidence": 0.97, "margin": 0.95}
```

- `fields` — top-k по подполю: целые значения и вероятности по убыванию.
- `records` — top-N целых записей, если их дал декодер.
- `hour24` — строки, где на бланке было `24:00`. Время хранится как 00:00 следующих суток.
- `confidence` и `margin` есть только у декодера.
- Нужны: dataclasses, чтение и запись, валидация (подполя из списка, вероятности в [0, 1]).
- Если `records` нет, сборка записи из top-1 полей: год из манифеста; 24:00 превращается
  в 00:00 следующего дня; переход дня берётся как есть.

### 2. `ocr_lab/evaluate.py`

Запуск: `python -m ocr_lab.evaluate --pred <file.jsonl> --split val [--out <dir>]`.
Истину брать из `data/ocr/manifest.csv`, уже с поправками.

**Метрики подполей:**
- top-1 и top-3 точность;
- NLL и ECE (калибровка), если есть вероятности;
- покрытие: доля подполей с предсказанием;
- разрезы: подполе, часть (`day`/`month`/`hour`/`minute`), буксир, печатное или рукописное
  (из `data/ocr/labels/printed_flags.csv`, если файл есть), год.

**Метки времени.** Строка верна, если совпадает datetime. `24:00` дня D равно `00:00`
дня D+1.

**Ваучер:**
- все 4 строки верны;
- то же плюс номер.

**Деньги:**
- распределение `|Δ work_minutes|` и `|Δ busy_minutes|`: среднее, p95, максимум, доля > 0;
- доля ваучеров, где сменился ночной флаг начала работ;
- доля, где сменилась дата окончания (курс).
Функции расчёта интервалов и ночи переиспользуй из `app/services/calculation.py`, если
их можно вызвать без сети. Выходные и праздники не трогай: там нужен внешний календарь.

**Автоприём (для декодера):**
- кривая «покрытие — точность» по `confidence`;
- `threshold_for_precision(target=0.995)`: порог, покрытие, точность и её 95 %
  доверительный интервал Уилсона;
- если выборка слишком мала, чтобы подтвердить цель, отчёт говорит об этом прямо.

**Отчёт:** `report.md` и `metrics.json` в `--out` (по умолчанию `data/ocr/reports/eval_<source>_<split>/`).

### 3. Тесты: `tests/ocr/test_evaluate.py`

Синтетическая истина и предсказания: точное совпадение, одна неверная минута, 24:00 против
00:00, переход через полночь, смена ночного флага, порог автоприёма на игрушечных данных.

## Критерии приёмки

- Отчёт по «идеальным предсказаниям», собранным из самой истины, даёт 100 % по всему.
  Добавь это как тест или команду.
- Проверки из `_common.md` зелёные.
