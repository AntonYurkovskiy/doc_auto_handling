Классификация регионов ваучера вместо свободного OCR
Проект doc_auto_handling: ваучеры распознаём НЕ через свободный OCR, а как предсказание + классификация по малому множеству. Ключевая идея и структура регионов бланка — ниже.

Смена подхода: OCR → «сначала предсказываем, потом распознаём»
Работа буксиров регламентирована, поэтому большинство полей ваучера выводится из открытых заявок и логики рабочего процесса (движок предсказания даёт приоры), а картинка нужна лишь как подтверждение/добор. Это превращает распознавание рукописи в классификацию по малому известному множеству вариантов, а не в OCR с нуля:

буксир — 2 класса (БК Коммунар / БК Пионер);
судно — кандидаты = несопоставленные заявки (обычно 5, макс ~10);
вид работ — после автомата состояния судна остаются единицы вариантов;
день — ±3 от дня заявки; часы — 25 классов; минуты — кратны 10 → 6 классов. Слияние: posterior = prior(предсказание) × likelihood(картинка). Всё локально, без внешних vision-API.
Авторазметка «бесплатно» из БД
Историческая выгрузка содержит проверенные итоговые значения каждого поля и колонки с именами файлов (Ваучер, Заявка). Метка для каждого скана берётся из БД автоматически по связи строка выгрузки → имя файла скана. ~700 сканов за 11 мес. → 700 размеченных примеров на поле без ручной разметки. Буксир для истории вообще не распознаём — он в суффиксе имени файла (k=Коммунар, p=Пионер).

Регионы бланка ваучера (CamScanner, шаблон «Baltiyskie buksiry», фиксированный макет)
Печатные зоны (впечатаны в шаблон перед печатью, распознаются надёжно OCR/по множеству):

Буксир (Tugboat): БК Коммунар / БК Пионер;
Судно (Vessel / объект работ);
Агент (Agent);
Вид работ (Order): одно из 21 значения корп-формы.
Рукописные зоны (вписаны ручкой, классификация по суженному множеству, не свободный OCR):

№ ваучера;
Выход из базы (дата + время);
Приход в базу (дата + время);
Начало работ (дата + время);
Окончание работ (дата + время);
«Работа выполнялась совместно с …» (количество / список буксиров);
Remarks / примечания. Подписи и печати перекрывают низ бланка, но НЕ перекрывают поля дат/времён.
Что нужно от заказчика для разметки регионов
30–50 сканов ваучеров с проверенными правильными значениями (метки берутся из выгрузки БД по имени файла), желательно в паре с их заявками — для настройки координат зон и обучения.
Подтверждение стабильности макета бланка (одна версия или есть варианты/повороты).
Одна эталонная разметка координат зон на репрезентативном скане (bounding-box каждого поля) — вручную один раз; далее применяется ко всем сканам после дескью/выравнивания.
Для надёжного покрытия редких случаев (переход месяца/года, лёд, нестандартные минуты) желательно добрать выгрузку до ~1500–2000 строк (1.5–2 года).
Целевые поля ваучера (контракт корп-формы WMS tugvhr)
Буксир (tvhr11), Объект работ/судно (tvhr15), Вид работ (tvhr13, 21 вариант), Агент (tvhr14), № ваучера (tvhr01), Выход из базы (tvhr02), Приход в базу (tvhr03), Время занятости (tvhr04= приход−выход), Начало работ (tvhr05), Завершение работ (tvhr06), Время работ (tvhr07=завершение− начало), Примечания (tvhr08), Брутто/нетто (tord11), Сумма (tvhr16), Валюта (tvhr17), Курс (tvhr18), Выручка руб (tvhr10=сумма×курс).
