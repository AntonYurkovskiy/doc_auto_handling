При работе над репозиторием AntonYurkovskiy/doc_auto_handling: доменная модель, модели БД (суда, судозаходы, операции, ваучеры), расчёт тарифов, загрузчик истории, приём почты.
Доменная модель сервиса обработки заявок/ваучеров буксиров (doc_auto_handling). Правила от владельца — соблюдать при проектировании моделей и логики.

Суда (Vessel) — только постоянные данные
Справочник постоянных характеристик судна, которые НЕ меняются во времени: имя, ИМО, флаг, LOA (длина), ширина, GRT, NRT. Одна запись на судно, переиспользуется между заходами. ВАЖНО: осадка (draft) — НЕ постоянная величина, её НЕЛЬЗЯ хранить в Vessel. Осадка привязывается к конкретной операции/заходу.

Судозаход (PortCall) — упорядоченная последовательность операций
Один судозаход = группа операций одного визита судна в определённой последовательности.

Минимальный набор: Швартовка → Отшвартовка (именно в таком порядке).
Между ними могут быть одна или несколько Перешвартовок.
Пример полной цепочки: заявка на вход → ваучер на швартовку ( или ваучер на швартовку + сопровождение, если осадка близка к ~9.6) → [перешвартовка(и)] → отшвартовка (± сопровождение). Всё это — ОДИН судозаход.
Операция (Operation) — элемент судозахода
Каждая операция: тип (швартовка / перешвартовка / отшвартовка / сопровождение), порядковый номер в последовательности, ОСАДКА судна на момент операции, связь с ваучером(ами) и расчётом.

Тип операции из направления заявки: вход → швартовка, выход → отшвартовка. В историческом датасете тип берётся из колонки work_type (нормализация), если пусто — из direction.
Сопровождение (правило): если осадка судна в заявке близка к 9.6 м (диапазон ~9.3–9.6 м), то ВЕРОЯТНО (не 100%) у ОДНОГО из двух буксиров к его операции добавляется сопровождение (на вход: у одного «сопровождение + швартовка», у второго просто «швартовка»; на выход: у одного «отшвартовка + сопровождение», у второго просто «отшвартовка»). Сопровождение бывает только у ОДНОГО буксира по заявке — одновременно у двух буксиров по одному судну сопровождения не бывает (вероятность близка к нулю).
Число буксиров на операцию: одна операция может выполняться ОДНИМ или НЕСКОЛЬКИМИ буксирами — зависит от длины судна (пороги LOA → число буксиров см. tugs_numbers_rules.odt). Требование «два буксира на одну операцию» уже озвучено. Значит связь операция↔буксиры — many-to-many, не одиночный tug_id.
Нумерация ваучеров
Нумерация сбрасывается 1 января и ведётся отдельным счётчиком по каждому буксиру. Номер определяется в пределах (буксир, год). Маркер копии «(N)» в имени файла (напр. 262k(2).pdf) игнорируется — это тот же номер. Коды k/p в исторических именах — коды буксиров. Это даёт предсказание следующего номера: max(номер за (буксир, год)) + 1.

Тарифные группы агентов
A = Транс-Агро; B = Терминал, Содружество-Соя; C = прочие. (Реальные ставки — плейсхолдеры, менять только по отдельному подтверждению.)

Прочее
Курс — ЦБ РФ; выручка в рублях. Ночь = 22:00–06:00 (надбавка). Ледовые условия — отдельный тариф.
Файл tugs_numbers_rules.odt (в data/historical) содержит точные правила «длина судна → число буксиров» и порог осадки для сопровождения — источник истины для числовых порогов.
