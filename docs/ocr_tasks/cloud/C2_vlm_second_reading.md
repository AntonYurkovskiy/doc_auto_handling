# C2. Второе прочтение всех ваучеров истории

Вариант В из `docs/ocr_tasks/cloud_alternative.md` — **только как инструмент разработки**.
Запускать, если владелец разрешил показывать кропы модели (Q5 в `DECISIONS.md`).
Прод не меняется.

## Зачем

Истина шумная: 4 из 11 нарушений цепочки оказались ошибками выгрузки. Шум в метках
портит и обучение, и оценку порога. T04 проверила около 70 ваучеров. Эта задача читает
**все** ваучеры по плиткам из 17 кропов и находит расхождения с выгрузкой **до**
обучения CNN.

## Что сделать

1. **Плитки.** Для каждого скана с кропами собери `data/ocr/review/tiles/<scan_id>.png`,
   около 1200×600: сетка кропов с подписями полей (`Выход: день | мес | час | мин`, …,
   `№`). **Истину на плитку не выводи**: чтение должно быть независимым.
2. **Чтение пачками по 20 плиток.** Посмотри плитки и запиши в
   `data/ocr/review/second_reading.csv`:
   - `scan_id`, поле, прочитанное значение, уверенность (`high`, `mid`, `low`);
   - `alt` — вторая версия, если сомневаешься.
   - Сверять с истиной во время чтения нельзя.
3. **Сравнение с истиной** — после чтения, скриптом. Расхождения при уверенности `high` —
   кандидаты в поправки: добавь их в `data/ocr/truth_corrections.csv` со
   `status=proposed`, `source=C2`. Их подтвердит человек (точка H1 или отдельный проход).
4. **Отчёт:**
   - доля совпадений по полям — это грубая оценка «потолка» распознавания;
   - число кандидатов в поправки по типам ошибок: сдвиг дня, перепутанные строки,
     минуты.

## Ограничения

- 774 плитки — это много чтений. Размер **L**, до 200 ходов. Если не укладываешься,
  обработай по порядку сплитов (сначала `train`) и заверши со статусом «частично»:
  повторный запуск продолжит с места остановки по CSV.
- Картинки уходят в API модели. Задача допустима, только если Q5 = «да».
