# Ежемесячный цикл дообучения и мониторинг (T28)

Инструкция для оператора: как запускать цикл раз в месяц, где смотреть отчёты и как
переключить/откатить версию модели в проде. Детали реализации — в докстрингах
`ocr_lab/export_confirmed.py`, `ocr_lab/manifest.py` (`combine`), `ocr_lab/retrain.py`,
`ocr_lab/monitor.py`; решения без человека и цифры сухого прогона — в `docs/ocr_tasks/
PROGRESS.md`, раздел «T28».

## 1. Зачем

Каждый подтверждённый оператором ваучер — новый обучающий пример (план, «Этап 6»). Раз в
месяц такие ваучеры добираются в обучающую выборку вместе с замороженной историей,
модели переобучаются и автоматически сравниваются с текущей прод-версией. Продвижение
происходит только если новая версия не хуже текущей по покрытию при целевой точности —
иначе прод не трогается.

## 2. Как запускать цикл

Из корня репозитория, интерпретатором `.venv` (сам `retrain.py` ходит в БД приложения
через `app.database.SessionLocal`; тяжёлые шаги обучения/калибровки/экспорта сами
запускают `.venv-train` отдельным процессом — переопределяется `OCR_TRAIN_PYTHON`):

```bash
export OCR_DATASET_CSV="<путь к reconciled_dataset.csv>"   # см. CONTEXT.md, если истина не на диске по умолчанию
.venv/Scripts/python -m ocr_lab.retrain run
```

Раз в месяц, после того как операторы подтвердили ваучеры прошлого месяца. По умолчанию:

- `--as-of` — сегодня; holdout (`test`) — последний **полный** месяц перед этой датой,
  `val` — месяц перед ним, всё раньше — `train` (`ocr_lab.manifest.monthly_boundaries`);
- версия цикла — `v<ГГГГММ>` даты запуска (например, `v202611` при запуске в ноябре);
- сравнение — с версией из `data/ocr/models/current_version.txt` (нет файла — `v1`);
- целевая точность — 99,5 % (`--target`, тот же показатель мониторинга, что в T21/T22 —
  не всегда подтверждается на выборке такого размера, это ожидаемо).

Полезные флаги:

- `--dry-run` — выполнить все шаги (включая обучение), но не применять продвижение
  (`current_version.txt` не меняется). Так проверяют цикл без риска сдвинуть прод.
- `--max-minutes N` — ограничение на каждый тяжёлый шаг (обучение/оценка) отдельно; при
  остановке по времени команда завершается кодом 3, повторный запуск **той же команды**
  продолжает с прерванного шага (`--resume` внутри `train_digits`/`train_number`
  подставляется автоматически).
- `--force` — пересчитать уже готовые шаги заново (по умолчанию готовые шаги
  пропускаются — цикл идемпотентен).
- `--as-of ГГГГ-ММ-ДД`, `--version`, `--current` — явно задать дату/версию/с чем сравнивать
  (например, чтобы повторить цикл для конкретного прошедшего месяца).

Один полный проход — манифест → страницы/кропы новых сканов → обучение `digits`/`number`
→ калибровка → экспорт в ONNX → приоры декодера/номера/пары → сквозная оценка на holdout
(новая версия и текущая прод) → сравнение → продвижение.

## 3. Где смотреть отчёты

- `data/ocr/retrain/<version>/report.md` — итог прохода: решение о продвижении и причина,
  покрытие/точность новой и текущей версии на `test`, число строк манифеста по источнику
  (`history`/`app`) и сплиту.
- `data/ocr/retrain/<version>/combine_report.md` — манифест цикла: сколько строк
  подтверждённых ваучеров отсечено как дубли истории (по `sha256` и по ключу
  буксир/год/номер), сколько конфликтов дедупа.
- `data/ocr/reports/e2e_retrain_<version>_new_report.md` и
  `..._vs_<текущая версия>_report.md` — подробная сквозная оценка (как в T21/T22) новой и
  текущей версии на одном и том же holdout.
- `data/ocr/models/current_version.txt` — какая версия сейчас рекомендована (обновляется
  только при продвижении без `--dry-run`).

Мониторинг за прошедший месяц (доля автоприёма, правки по полям, разрезы и
предупреждения) — отдельной командой:

```bash
.venv/Scripts/python -m ocr_lab.monitor --month 2026-09
```

Отчёт — `data/ocr/reports/monitor_<месяц>.md`:

- доля автоприёма и доля правок оператором по номеру ваучера и 4 строкам дат;
- разрез по буксирам, по слотам вахт (буксир + слот, формула T23: смена в 09:00, ротация
  4 суток) и по вариантам бланка (переопределяется выравниванием, не требует моделей цифр);
- предупреждения: всплеск правок в одном слоте одного буксира (возможно, в вахте новый
  человек) и доля отказов выравнивания выше 5 % в одном варианте бланка (возможно, новый
  бланк на буксире). Оба порога — решения без человека T28, см. журнал; при частых
  срабатываниях вхолостую их стоит пересмотреть по статистике нескольких месяцев.

В отчётах — только агрегаты, коды буксиров (`k`/`p`) и `id` ваучеров, без имён судов,
агентов и текстов.

## 4. Переключение и откат версии модели

Версии лежат рядом в общем каталоге `data/ocr/models/` (`digits_<версия>/`,
`number_<версия>/`, `decoder_priors_<версия>.json` и т. д.) — то же, что уже умеет рантайм
приложения (T18/T22, `app/ocr/runtime.py`).

- **Прод читает версию** из `Settings.ocr_model_version` (`APP_OCR_MODEL_VERSION` в
  окружении/`.env`), по умолчанию `"v1"`. `current_version.txt`, который обновляет
  `retrain.py` при продвижении, — только **рекомендация** для человека: он не читается
  приложением автоматически.
- **Чтобы переключить прод** на новую версию — после того как вы посмотрели отчёт T28 и
  согласны с продвижением: выставьте `APP_OCR_MODEL_VERSION=v<версия>` и перезапустите
  приложение (ресурсы пайплайна кэшируются в памяти процесса на старте, `app.main.
  _warm_up_ocr`, см. T25/T26 — на лету версию не подхватит).
- **Откат** — та же операция в обратную сторону: выставьте `APP_OCR_MODEL_VERSION` на
  предыдущую версию (например, обратно `v1`) и перезапустите приложение. Старые версии в
  `data/ocr/models/` не удаляются автоматически — удалять их вручную не раньше, чем
  убедитесь, что откат больше не понадобится.
- Если отчёт показал, что новая версия хуже (даже при автоматическом отказе от
  продвижения) — прод не трогается сам по себе, никаких действий не требуется.
